# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Vite, React, and TypeScript for the web application foundation.

## Users

Field deployment engineers (FDEs) preparing to understand a customer's existing technical environment.

## Product Purpose

Help an FDE translate large volumes of descriptive customer documentation and approved technical access into a reviewable, executable understanding of an integration.

## Positioning

The product connects source documentation and technical access to structured integration knowledge instead of leaving that translation scattered across notes and manual investigation.

## Operating Context

An FDE begins with customer-provided documentation, often including Confluence content, and may receive approved API access or credentials. The intended outputs are an integration map, API inventory, auth model, schema mapping, data model, and potential risks.

## Capabilities and Constraints

- This commit is a UI and repository skeleton only.
- The eventual product must support customer documentation and approved API access.
- No connector, credential handling, upload, ingestion, extraction, or analysis behavior is implemented yet.
- Data handling, authentication provider, deployment target, and AI/extraction approach remain undecided.

## Evidence on Hand

No customer documents, credentials, technical schemas, integrations, benchmarks, or brand assets were supplied. The interface must not fabricate them.

## Product Principles

1. Keep source material and derived understanding distinguishable.
2. Make technical conclusions reviewable before they become implementation decisions.
3. Treat customer access and credentials as sensitive boundaries.
4. Prefer structured, usable integration knowledge over untraceable summaries.
